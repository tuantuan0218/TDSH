# pollinations 预算波动实测 + 一次"假相关"纠错 — 2026-09-13

> 承接上轮：我用知识门把 pollinations 判为"预算耗尽"。
> 本轮深挖后**发现该判定过于简单**：其预算状态在**分钟级波动**，
> 且我在中途**误把时间差异读成了内容相关**，特此记录纠错。

## 一、最终结论（三句话）

1. **pollinations 是真端点**（多次给出正确推理结果），**不是假服务**
2. 其 keyless 预算状态**在分钟级波动**：同一 prompt 可能这一刻成功、下一刻返回预算文本
3. 返回的**始终是 HTTP 200**，预算提示写在正文里 → **只看状态码必误判**

  成功出词 : 10

**同一 prompt、同一代码、同一分钟内翻转** → 变量是**时间/预算**，与内容无关。

## 三、⚠️ 我中途犯的错：把时间差异误读成"内容相关"

### 错误过程

我做了 A/B 交替测试（A=`PONG`题、B=`17*23`题）：

```
第1轮  A:PONG题=OK   B:17*23题=BUDGET
第2轮  A:PONG题=OK   B:17*23题=BUDGET
...（6 轮完全一致）
A(PONG题)  成功 6/6
B(17*23题) 成功 0/6
```

**6 轮完全一致的分布**，看起来是**极强的内容相关性**（P=极小）。
我据此推断"prompt 含数字会触发 BUDGET"，并去隔离变量（试了汉字数字/英文拼写/拼音等）。

### 但隔离测试全 BUDGET，包括此前"
成功"的写法

```
汉字数字（无阿拉伯数字）  -> BUDGET
英文拼写算式           -> BUDGET
拼音混合               -> BUDGET
含阿拉伯数字            -> BUDGET   ← 此前成功过
阿拉伯数字但非算式        -> BUDGET
无数字的算术            -> BUDGET
```

**全灭** → 说明前面的 A/B 差异**不是内容造成的**。

### 真正的解释

回顾时序即可发现：A/B 交替测试**恰好落在预算状态切换的窗口内**——
A 先发（那时预算可用）、B 后发（那时已耗尽），
且因两者交替间隔稳定，**每一轮都重复了同样的先后顺序**，
于是产生了"内容相关"的**完美假象**。

> 📌 **教训**：**当两个变量（内容、时间）在同一实验里同时变化时，`,
> 交替测试会因顺序固定而产生假相关。**
> 正确做法：**对同一 prompt 重复多次**（我最后做的就是这一步），
> 或**打乱顺序 / 双盲**，以把时间因素与内容因素分离。

这与本会话此前反复强调的纪律一脉相承：
**"6 次一致"不等于"因果关系"，可能是未受控的第三个变量。**

## 四、对池的实际含义

| 项 | 结论 |
|---|---|
| pollinations 是否真端点 | ✅ 是（有真实推理输出，如 `2+2` → `4`） |
| #18 为何被停用 | 当时确实打满 785 次/天，**停用是正确的止血** |
| #21/#22 状态 | `active`+`schedulable`，但指向同一预算池；**预算波动时会间歇失败** |
| 失败表现 | **HTTP 200 + 预算文本**（非 4xx）→ 依赖 `BAD_OUT` 识别 + `error_rate` 避让 |
| 是否该改配置 | **不建议**：它是波动的备用能力，尾部账号本就少有流量；`error_rate` 会自动避让 |

**结论**：上轮"预算耗尽"的判定**在那一刻是对的，但不宜作为该端点的长期定性**。
准确表述是：**"预算受限、分钟级波动、仍可间歇使用"**。
