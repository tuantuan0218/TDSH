# dsh-global-agent 交接文档

## 功能

TDSH 设置面板 → 全局 Agent 指令：编辑 `$DSH_HOME/AGENTS.md`，保存后 dsh 内置 `agent-instructions` 插件自动热加载，下一轮对话生效。

## 架构

```
用户点击"全局 Agent 指令"（设置面板）
  → client.js 弹出模态编辑器
  → 用户编辑并点保存
  → POST http://127.0.0.1:24000/__tdsh/agent { content: "..." }
  → main.js carrier server 写入 $DSH_HOME/AGENTS.md
  → dsh agent-instructions 插件（SHA-1 digest 文件监听）
  → 检测到文件变化 → 注入 system-reminder → 下一轮对话生效
```

## 实现细节

### client.js
- 纯 DOM 操作，无 MutationObserver（已知会导致 dsh 渲染器卡在 "Loading plugins..."）
- 3 秒 polling 模式注入设置入口 + 检测面板是否被 React 卸载后重注入
- CSS 注入，模态框样式匹配 dsh 暗色主题
- 通过 URL 参数 `?dshDesktopPort=24000` 确定 carrier 基地址（同 update-btn 插件模式）

### Carrier 路由 (main.js)
- `GET /__tdsh/agent` → 读取 `$DSH_HOME/AGENTS.md`，不存在返回空字符串
- `POST /__tdsh/agent` → 写入 `$DSH_HOME/AGENTS.md`，自动创建目录
- 放在 carrier 路由最后（post-update 之后，404 之前）

### agent-instructions 重启用
- web-app bundle 的 cordis.patch.yml 设置了 `disabled: true`
- dsh-global-agent 的 cordis.patch.yml 设置 `disabled: false` 覆盖
- bundle 应用顺序：dsh-base → web-app → ... → global-agent（最后 = 生效）
- 内置监听 $DSH_HOME/AGENTS.md（`userGlobalDisplayPath()`），SHA-1 digest 比对，无变化不重注入

## 已知问题

- **profile 升级路径**：已安装的 0.1.26 用户不会自动获得 `dsh-global-agent` 插件，需要手动加进 profile 的 package.json bundles 列表并复制插件到 node_modules
- **agent-instructions 重启用仅在 cordis 层面**：如果 dsh 后续版本更改禁用机制，重新禁用可能覆盖此 patch
- **配置文件路径**：`$DSH_HOME/AGENTS.md` 是默认的 user-global 路径，如果用户设置 `DSH_HOME` 环境变量，路径跟随
